# Temporary Tanyora mobile UI review

## Safest approach
Add `/mobileapp` as a separate, temporary browser review page. Leave the website homepage, existing website routes, production Android screens, global CSS, shared configuration and backend unchanged. Do not publish or deploy.

The Android screens live in `mobile/`; the website lives in `src/`. Android components depend on React Native, Expo navigation, device pickers and other native services, which cannot simply be imported into this website. Use an isolated browser presentation matching the approved native Home design, reusing its artwork and safe existing data helpers where compatible. This is a UI review companion, not a replacement Android app or proof of native functionality.

## First stage: Home only
- Create the temporary route and reproduce the previously approved Home screen, including its floating bottom navigation and raised upload control.
- Keep Home, My Files, Upload, Shared Links and Profile destinations available. Only Home is recreated in this stage; other destinations show clearly identified review-pending states until you approve their stage. They must not display invented account data or pretend to support unfinished actions.
- Use the existing signed-in account for safe read-only file/profile information. If signed out, offer the existing sign-in page with a return destination; never create a second login system. Do not automatically upload, rename, share or delete real files.
- Reuse the existing native artwork without embedding the supplied editor screenshot as page content.
- Show the page in the preview at `/mobileapp`, then wait for your approval before implementing My Files.

## Following stages
After each approval, add one screen: My Files, Upload, Shared Links, then Profile. Match its supplied reference and preserve the approved navigation geometry. Connect compatible existing actions only where safe, using explicit confirmation for changes to real files/accounts. Native-only capabilities remain identified as requiring Android testing; Camera/Drive must not appear functional without their integrations.

## Isolation and technical details
Proposed new files:
- `src/routes/mobileapp.tsx`: temporary leaf route, unique Tanyora metadata and `noindex`.
- `src/components/mobileapp-review/`: clearly named, temporary screen, navigation and read-only data adapters.
- `src/components/mobileapp-review/mobileapp-review.module.css`: locally scoped styling/tokens, not global CSS.
- Tests beside temporary helpers only when behavior rules are introduced; browser scripts/screenshots under `/tmp/browser/`.

Use the existing backend client/session and query provider, not a second backend or auth client. Do not add React Native aliases, dependencies or change the website configuration merely to render the native screens. Automatic route registration is generated by the existing router; do not hand-edit it.

The root already supplies splash behavior, authentication notifications and host redirects. Keep these untouched. Review `/mobileapp` in the preview; on the owner's main domain the existing host rule may redirect it to the web subdomain. Removing that behavior or suppressing the inherited splash requires your separate approval.

Record the temporary implementation boundary in `AGENTS.md` and track review stages in `roadmap.md`; these documentation changes do not affect the running website.

## Checks and limits
- Check Home layout, scrolling, navigation state, accessible controls, portrait/landscape widths and no horizontal overflow.
- Check `/` and existing sign-in still load unchanged, and inspect console/build errors.
- Verify signed-in read-only data when a suitable account/session is available; otherwise report it as unverified, not passed.
- Browser checks cannot verify Android safe areas, native permissions, system pickers, AdMob, app deep links or native playback. Those require a real Android device/emulator.
- Do not run destructive account deletion as a review test.

## Cleanup
Keep `/mobileapp` until you explicitly approve its removal. Then delete only newly introduced temporary route/components/styles/tests, remove their documentation references, verify original routes and report every deleted or modified file. Preserve production/native/reusable code and do not publish.
