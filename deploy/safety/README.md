# Self-hosted upload safety

This directory runs only on the owner's Linux VPS, never inside TanStack SSR or a Worker bundle.

## Active controls
- `content-safety.sql`: private quarantine, immutable file identity, server-controlled scan/review state, owner/admin metadata reads, approved-only sharing/conversion, blocked-account checks, serious authenticated report holds, audit events and no rewards for restricted files.
- `storage-policy-fix.sql`: already-applied correction qualifying storage object names; only needed after the first deployed version of the migration, not after the corrected main SQL.
- `service.py` and `policy.py`: one bounded antivirus worker and a loopback-only Nginx authorisation guard. Clean supported scans automatically enable sharing; failed scans, existing blocks and report holds never auto-release.
- `automatic-sharing.sql`: releases only initial malware-clean approval waits, not open reports or blocked files. Apply after the main safety SQL.
- `tanyora-safety.service`: restartable service; credentials in root-only `/opt/tanyora-safety/service.env`. The host database address comes from the current Docker database container. Refresh it after network changes.
- Nginx must apply `auth_request /_tanyora_safety_check` to object and render delivery paths, forward the original URI and bearer, use HTTP/1.1, and never cache file responses. Keep the existing Docker external-port firewall restrictions.
- `scan_config.py` validates `SAFETY_MAX_SCAN_BYTES` (default 100 MiB) against the exact `SAFETY_CLAMD_CONFIG` (default `/etc/clamav/clamd.conf`) used by `clamdscan`. `MaxFileSize`, `MaxScanSize` and `StreamMaxLength` must cover that ceiling; `AlertExceedsMax`, `AlertEncrypted` and `ScanArchive` must be `yes`. Invalid/unverified configuration fails closed. Definitions must refresh through `clamav-freshclam`.
- One database advisory lock serializes workers; timestamp claims reject stale results after interruption/requeue. Temporary disk headroom and full transfer size are checked before antivirus; scan errors/warnings never imply clean.

## Limits
Selected images, video, audio, PDF, text and DOC/DOCX/XLS/XLSX/PPT/PPTX are supported by the source scanner. Office containers undergo bounded signature/structure checks and then complete antivirus inspection including embedded content; encrypted, malformed and incomplete scans remain private. Arbitrary archives and executables remain prohibited. Unsupported/error results now remain pending and unshareable rather than becoming permanent moderation blocks. Malware blocks and moderation/report holds persist across every storage-path copy.

The default remains 100 MiB until actual VPS capacity is verified. A larger limit requires aligned antivirus settings, daemon restart, adequate temporary disk/memory, tested full transfers and scan timeouts. `SAFETY_SCAN_TIMEOUT_SECONDS` defaults to 180; longer full-file scans may require a verified higher value. ClamAV's per-file ceiling is below 2 GiB; a 1 TB upload is not a promise of shareability. Do not disable `AlertExceedsMax`, split files into chunks, or approve skipped scans to work around it. A different verified scanner is needed beyond this engine's ceiling.

Paid automated media moderation and specialist child-abuse hash matching are not connected. Initial human approval is not required; antivirus does not classify illegal sexual material. Safety reports and explicit blocks still require investigation. No detection guarantee is made. Previously delivered/downloaded copies cannot be recalled.
